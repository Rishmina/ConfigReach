What it measures

Coverage that follows configuration behavior.

ConfigReach keeps observable metrics separate. Unknown domains stay unknown instead of being converted into an opaque score.

K

Key coverage

Which discovered configuration inputs have test or runtime evidence.

V

Value coverage

Which explicitly known values are exercised — including defaults and finite domains.

↕

Boolean & enum coverage

Track true/false states and discrete alternatives where a domain can be established.

⑂

Branch-state coverage

Connect configuration-dependent branches to explicit test-value evidence and source lines.

×

Combination coverage

Expose missing interacting key pairs and known pairwise value states.

Δ

PR blast radius

Use merge-base and changed-line slicing to surface configuration impact introduced by a pull request.

Quick start

From clone to configuration coverage in a minute.

1

Install from the repository

ConfigReach requires Python 3.11+ and has no runtime dependencies.

2

Scan your codebase

Run static analysis locally. No network access or model inference is required.

3

Gate new gaps in CI

Add thresholds, SARIF output, baselines or PR comments when you are ready.

git clone https://github.com/sauravsingla/ConfigReach.git
cd ConfigReach
python -m pip install -e .
configreach scan .

# CI policy examples
configreach scan . --fail-under 70
configreach scan . --fail-on error
Built for review

Make configuration changes visible before they become production surprises.

Use `configreach diff` to compare the merge base with your current tree, identify newly introduced keys or values, and focus review on configuration behavior touched by changed lines.

pull request analysis
